# Contributing to Time Debt Warrior ⏳⚔️

First of all, thank you for taking the time to contribute!  
Time Debt Warrior is an open-source project focused on tracking, visualizing, and fighting time debt through clean UI and meaningful interactions.

We welcome **bug reports, feature ideas, UI improvements, documentation updates, and code contributions**.

---

## 📌 Ways to Contribute

You can contribute in the following ways:

- 🐛 Reporting bugs
- ✨ Suggesting new features
- 🎨 Improving UI/UX
- 🧠 Improving logic or performance
- 📝 Improving documentation
- 🔧 Fixing existing issues

Before starting, please check the **Issues** tab to see if the issue already exists.

---

## 🛠️ Project Setup

1. **Fork the repository**
   - Click the `Fork` button on the top-right of the repo.

2. **Clone your fork**
   ```bash
   git clone https://github.com/<your-username>/time-debt-warrior.git
   cd time-debt-warrior
   ```
3. **Create a new branch**
   ```bash
   git checkout -b feature/your-feature-name
   OR
   git checkout -b fix/issue-name
   ```
---
## 🧱 Branch Naming Convention

Use meaningful branch names for example ,

feature/add-dashboard

fix/navbar-overflow

docs/update-readme

refactor/state-management

---

## ✅ Code Guidelines

Keep code clean and readable

Follow existing project structure

Avoid unnecessary files or console logs

Use meaningful variable and function names

Comment complex logic when needed

--- 

## 🧪 Testing Checklist (Before PR)

Before raising a PR, make sure:

 Code runs without errors

 No existing features are broken

 UI looks fine on different screen sizes (if UI-related)

 Linting / formatting is clean (if applicable)
 
---

## 🚀 Pull Request Guidelines

Before raising a Pull Request, please make sure you have:

- Forked this repository
- Asked to be assigned in the related issue’s comment section
- Created a dedicated branch for your work
- Linked the issue number in your PR

---

## 🧩 How to Submit a Pull Request

1. **Fork this repository**
2. **Ask for issue assignment**
   - Comment on the issue you want to work on and request assignment.
3. **Create a new branch**
   ```bash
   git checkout -b fix/issue-name
   ```

## 📝 Pull Request Format
PR Title
```bash
[Type] Short description of change
```
Examples:

[Feature] Add time debt analytics chart

[Fix] Resolve navbar overflow on mobile

[Docs] Update contributing guidelines   

Fill the PR description using the format below 👇

PR Description Template
```bash
## 📁 Files Changed
List all files that were modified in this PR.
- src/components/___
- src/pages/___
- styles/___

## ✨ Features Introduced / Fixes Applied
Clearly mention what was added, improved, or fixed.
- Fixed ___
- Added ___
- Improved ___

## 🏷️ Type of Pull Request
Select the relevant type:
- [ ] Bug Fix
- [ ] Feature Addition
- [ ] UI Enhancement
- [ ] Refactor
- [ ] Documentation Update

## 🐞 Issue Reference
Closes #<issue-number>

## 📸 Screenshots / Screen Recordings
Attach relevant screenshots or videos and **explain what was broken and how it was fixed**.

## 🧠 Why This Issue Was Important
A short explanation or anecdote describing:
- Why this bug/issue existed earlier
- How it affected the user experience or system behavior

## 🧾 Final Summary
A concise summary of the overall change and its impact.
```
## 📢 Raising an Issue

If you want to report a bug or suggest a feature:

Go to the Issues tab

Click New Issue

Use a clear title

Describe:

What is the issue?

Steps to reproduce (if bug)

Expected behavior

Screenshots (if applicable)

## 💬 Communication & Respect

Be respectful and constructive

Feedback is welcome — toxicity is not

Maintainers may suggest improvements before merging

## ⭐ Final Note

Every contribution matters — whether it's code, design, or ideas.
If you're stuck, open an issue or start a discussion.

Happy contributing! 🚀
